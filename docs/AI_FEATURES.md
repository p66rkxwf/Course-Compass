# Course Compass AI 功能說明

本輪新增三項 AI 功能，全部跑在本機，不需要雲端 API：

1. **中籤預測**：預測一門課登記會不會爆滿、選上機率多少
2. **選課助理**：用一句話描述需求，由 LLM 呼叫工具查課
3. **教學大綱搜尋與問答**：依內容找課、針對單一課程問大綱

每一項都附上基線比較與可重跑的評估，並寫明限制。

| 功能 | 技術 | 驗證 | 報告 |
|---|---|---|---|
| 中籤預測 | HistGradientBoosting＋conformal 區間＋isotonic 校準 | walk-forward 4 折＋115-1 held-out（只評估一次） | `docs/demand_model_report.md`、`docs/test_set_ledger.md` |
| 選課助理 | 本機 Ollama（qwen2.5:7b）tool calling，另有離線規則模式 | 30 則人工寫定條件的查詢 | `docs/agent_eval.md` |
| 教學大綱搜尋 | PDF 文字層 → 段落切塊 → bge-m3 向量＋字元 TF-IDF 混合 | 15 則換句話說的查詢，與字面基線比較 | `docs/rag_eval.md` |

## 1. 中籤預測

**問題**：選課時最常見的困擾是「這門課會不會爆、我選不選得上」。原系統只顯示歷年平均選上率，而且算平均時**把當學期自己也算進去**，等於偷看答案。

**做法**：
- **預測目標**：一門課的需求比 log(登記/上限)，並推得兩個數字：
  - **估計中籤率** = min(1, 上限/登記)，附 80% 區間
  - **爆滿機率** P(登記 > 上限)
- **特徵**（預測第 t 學期時只用）：
  - 第 t 學期公告的課程清單：上限、時段、學分、性質、備註、同時段競爭班數
  - **t 以前**的登記紀錄：同課名＋教師、同課名、同教師的歷史需求比，以及類別層級的上期壓力
- **防洩漏**：
  - 竄改測試：改動第 t 學期的登記人數，特徵必須不變（`tests/test_demand_features.py`）
  - 打亂標籤測試：5 個種子
  - 超參數固定、不在測試學期上調
- **區間與校準**：
  - 分位數迴歸加 conformal 校正，通識類和其他課分開校正
  - 爆滿機率用 isotonic 校準
  - 兩種校準都只用訓練學期的最後一期來做

**結果**（M = 模型、B0 = 歷年平均〔只用過去學期〕、B1 = 上學期）：

| | 開發折（113-1～114-2） | **held-out 115-1** |
|---|---|---|
| 全部課程 爆滿辨識 PR-AUC | M 0.653／B0 0.514／B1 0.384 | M **0.542**／B0 0.438／B1 0.347（base rate 0.083） |
| 全部課程 中籤率誤差 MAE | M 0.017／B0 0.022 | M **0.021**／B0 0.026 |
| 通識體育語文 PR-AUC | M 0.903／B0 0.887 | M **0.720**／B0 0.662 |
| 通識體育語文 中籤率誤差 | M 0.124／**B0 0.117（B0 較好）** | M **0.157**／B0 0.184 |
| 冷啟動（首次開的課）PR-AUC | M 0.364／B0 0.196 | M **0.530**／B0 0.324 |
| 80% 區間實際涵蓋率 | 全部 82.0%、通識 75.7% | 全部 **70.1%**、通識 **63.1%**（偏窄） |

**誠實邊界**：
- held-out 各項都贏 B0，但**數字全面低於開發折**，新學期有分布漂移。
- **80% 區間在 115-1 只涵蓋 70%**，介面上註明「區間在新學期常偏窄」。
- 通識的中籤率誤差在開發折是**輸給**歷年平均的（0.124 對 0.117），held-out 才轉贏。兩者都寫進報告，不挑有利的講。
- 打亂標籤測試的 ROC-AUC 是 0.416±0.028，偏離 0.5。原因分析寫在報告裡：六成爆滿課集中在通識類，打亂後的類別層級偏移造成高變異。這不是洩漏，洩漏只會讓它高於 0.5。
- 中籤率假設超額時隨機分發。實際有年級、學院等優先規則，所以只是近似值。

**資料面的發現**：原本的 114-2 資料是 2026/1/8 抓的，當時選課還沒結束。重爬後超額課程從 93 門增加到 163 門，已全部改用重爬的資料。

## 2. 選課助理（Agentic AI）

**流程**：
1. 使用者輸入一句話，例如「週五不要有課、2 學分通識、跟資料分析有關、不要太難搶」。
2. LLM 自行決定呼叫哪些工具，最多 5 輪。可用的工具有：
   - `find_courses`：條件篩選，並附中籤預測
   - `semantic_search_syllabus`：大綱語意搜尋
   - `get_course_detail`、`get_course_history`
   - `check_schedule_conflict`：檢查衝堂
3. 最後以 JSON schema 強制輸出 `{reply, suggestions}`。

**設計重點**：
- **工具共用既有邏輯**：課程篩選抽成 `src/services/recommend.py::filter_courses`，推薦 API 和助理用同一份程式碼。重構前後有 12 個 golden 案例逐筆比對（`tests/test_recommend_parity.py`）。
- **防幻覺**：LLM 建議的每一門課都用「課程代碼＋序號」回頭比對目標學期的資料，不存在就剔除，並在介面上顯示剔除了哪些。
- **透明**：介面可以展開看到助理實際呼叫了哪些工具、帶了什麼參數。
- **會參考「我的課表」**：自動排除已選的課和會衝堂的課。
- **離線模式**：沒有 Ollama 時自動改用規則解析器（`src/ai/parse.py`），介面會註明目前是哪種模式。

**評估**：30 則查詢，每則的「使用者條件」由人工寫定，不是由解析器產生，見 `data/eval/agent_queries.json`。

| provider | 條件滿足率 | 全部符合的查詢比例 | 幻覺率 | 有解卻空答 |
|---|---|---|---|---|
| 離線規則模式 | 86.2% | 80.8% | 0% | 0% |
| qwen2.5:7b（Ollama） | **尚未評估**：本次開發環境沒有安裝 Ollama | | | |

規則模式的失誤集中在它不認得的說法，例如「只有週三下午有空」「星期二」（沒有「只要」這類字眼）、「不會爆滿」。這正是 LLM 應該補強的地方。裝好 Ollama 後執行 `python main.py eval-agent`，就會兩種一起比較。

## 3. 教學大綱搜尋與問答（RAG）

- **資料**：115-1 共 1,895 門課，其中 1,636 門有大綱 PDF。
  - 以每秒最多 1 個請求的速度下載，並快取在 `data/syllabus/`（已加入 .gitignore）。
  - 直接讀 PDF 文字層、不做 OCR。
  - 清掉每份都一樣的樣板文字（問卷類型、教學型態選項），並接回被拆成一字一行的直書表格。
- **切塊**：依「教學目標／教學大綱／評量方式／教材／教學進度…」切段落，每塊約 500 字、重疊 80 字，並在塊前加上課名與段落名。
- **搜尋**：bge-m3 向量相似度與字元 bigram TF-IDF 各占一半，查詢字串原文命中時額外加分。權重固定為 0.5，沒有針對評估題目調整。
- **問答**：只取該課程最相關的 3 段給 LLM，要求逐句標註引用編號，段落裡沒有的資訊就回答「大綱沒有寫」。介面會附上引用的原文。
- **評估**：見 `docs/rag_eval.md`。「相關」的定義是大綱含有事先寫定的相關詞，屬於代理標註。
  - 115-1 全部 1,636 份大綱都有可讀的文字層，切成 15,623 塊。
  - **本次開發環境沒有 Ollama，索引用的是離線 mock embedding（字元雜湊），沒有語意能力**。在這個條件下的結果：

    | 方法 | P@5 | P@10 | Hit@5 | MRR |
    |---|---|---|---|---|
    | 混合（系統採用） | 0.720 | 0.593 | **1.000** | 0.836 |
    | 純向量（mock） | 0.467 | 0.427 | 0.867 | 0.648 |
    | 基線：整篇字面 TF-IDF | **0.747** | **0.700** | 0.933 | **0.841** |

  - **離線模式下，混合搜尋和字面基線大致打平**：P@5、P@10 基線略好，Hit@5 混合較好。目前還沒有證據顯示「語意搜尋」勝過字面比對。要驗證語意能力，需要安裝 Ollama、`ollama pull bge-m3`、重建索引，再跑 `python main.py eval-rag`。

## 如何執行

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt

python main.py crawl --semesters 114-2 115-1   # 爬指定學期（查詢頁已改為 MVC，爬蟲已更新）
python main.py process                          # 產生 data/processed/all_courses_*.csv
python main.py train-demand                     # walk-forward 評估＋訓練凍結模型＋報告
# python main.py eval-holdout                   # 只在模型凍結後執行一次，會寫入 test_set_ledger.md

# 選課助理與大綱搜尋需要本機 Ollama（https://ollama.com/download）
ollama pull qwen2.5:7b && ollama pull bge-m3
python main.py fetch-syllabi                    # 下載當學期大綱（約 1,600 份，需時 1～2 小時）
python main.py build-index                      # 建立大綱向量索引
python main.py eval-agent && python main.py eval-rag

python main.py api                              # http://localhost:8000
AI_PROVIDER=mock python main.py api             # 沒有 Ollama 時用離線規則模式展示
.venv/bin/python -m pytest                      # 40 個測試
```

## 生成式 AI 使用說明（競賽申報用）

- **系統內**：選課助理與大綱問答使用本機開源模型 qwen2.5:7b（Ollama），向量搜尋使用 bge-m3。課程資料不會送到雲端。
- **開發過程**：程式撰寫與文件整理有使用 AI 程式助理（Claude Code）協助。模型設計、驗證結果與限制，都以本文件所列、可重跑的腳本與測試為準。
